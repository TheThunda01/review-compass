# Assumptions and their consequences

The planner contains no biological prediction model and makes no scientific eligibility decision. These are the material choices behind its prompts, scanner, and search records.

| Assumption or choice | Why it is used | How it is checked | Consequence if it fails |
| --- | --- | --- | --- |
| Users choose a review purpose before adapting prompts. | Different synthesis questions need different methods (Nussbaumer-Streit et al., 2025). | Not established by selecting a dropdown; discuss the purpose with an experienced reviewer. | A polished draft can still use an unsuitable design. |
| PICO, PCC, SPIDER, and CMO are starting structures. | They make some question elements explicit. JBI suggests PCC; Cooke et al. (2012) proposed SPIDER with a call for wider testing. | No comparison of framework effectiveness is performed. | A framework may omit relevant concepts or encourage an overly restrictive search. Adapt it; do not turn every field into a mandatory search block. |
| Full words and phrases are useful things to display. | Literal matching is inspectable and bounded. This is a software convenience, not a semantic model. | Tests cover punctuation, Unicode, partial words, negation, and missing text. | Relevant synonyms may be missed and negated phrases may match. Every record remains for human review. |
| Nonempty fields and mention cues can describe text entry. | They help users find unfinished drafting steps. | The app counts entered fields and displays the narrow meaning. | A single character or a statement of intent is not a valid protocol or completed task. |
| The user supplies accurate record-flow counts. | The calculator checks arithmetic, not the underlying screening log. It assumes each retained record corresponds to one report and combines source pathways; real reviews need record-to-report reconciliation. | Numeric constraints and arithmetic are tested; source counts are unverified. | Consistent arithmetic can still mix records, reports, and studies or conceal missing records. |
| Search syntax must be tested in its intended platform. | PubMed and other databases differ in mapping, field tags, and phrase handling. | The scanner checks only listed lexical features; platform execution is external. | Balanced delimiters do not establish valid syntax, high recall, or a useful search. |
| Metadata describe what the operator knows. | PRISMA-S motivates retaining context, while the tool has no database connector. | Required fields and value types are checked, not truthfulness. | `reported_executed` and a date do not prove a search occurred. |
| Unknown count and explicitly reported zero must remain distinct. | Missing evidence must not be silently converted into a numerical claim. | `null` is allowed for unknown counts; drafts require it; safe-integer validation rejects invalid counts. | Interchanging zero and unknown can misstate the search history. |
| Exact bytes are the unit for a file fingerprint. | This makes alterations detectable without interpreting their meaning. | SHA-256 is recomputed; predecessor query text must match its stored fingerprint. | Reformatting changes a digest; a fabricated but internally consistent record can still pass. |
| A single immediate predecessor is enough for the current recorder. | This is a bounded implementation choice inspired by provenance relationships (W3C, 2013). | The visible predecessor and its immediate link are checked; older ancestry is not traversed. | Missing older records, distant cycles, authorship, or a complete history are not established. |
| The selected browser storage mode suits the user's environment. | The implementation allows local storage for the hostname strings `localhost`, `127.0.0.1`, an empty string (local files), and `::1`; other strings use tab memory. Browsers usually expose IPv6 localhost as `[::1]`, which is not in this list. Storage failures fall back to memory. | Code gates storage by hostname and handles storage errors. | Shared-device access and downloaded exports may expose notes; no institutional data-governance approval is implied. |
| Synthetic examples can demonstrate defined behavior. | Fixtures allow repeatable checks without private review data. | Existing tests check matching, exports, schemas, limits, and revision behavior. | Usability, time savings, recall, and scientific benefit remain untested. |

The [reference list](references.md) and [source audit](reference-audit.json) distinguish guidance from empirical findings. No filled-field count, source citation, or passing test independently validates a review.
